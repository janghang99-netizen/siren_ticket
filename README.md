# SIREN — 공연 티켓 + 공연장 입점매장 사이렌오더

- **좌석티켓**은 플랫폼 회사(슈퍼어드민)만 운영한다 — 공연 일정을 여러 개 등록하고, 구역별 가격·좌석 수를 정하고, 판매·취소를 관리한다.
- **사이렌오더**는 여러 입점업체가 운영한다 — 한 업체가 여러 매장을 갖고, 매장마다 상품·주문을 관리한다. 운영사는 업체별로 정산한다.

다담다(PHP 5.2) 사이렌오더를 Laravel 12로 옮기고 티켓 예매를 붙였다. 이전 내역은 [docs/MIGRATION_SPEC.md](docs/MIGRATION_SPEC.md).

## 실행 (Docker · MySQL 8.4)

```bash
docker compose up -d --build
```

- 사이트: http://localhost:8090 · 관리 로그인: http://localhost:8090/login
- 첫 기동 시 마이그레이션 + 데모 데이터가 자동으로 들어간다. 처음부터 다시: `docker compose down -v && docker compose up -d --build`
- 미결제 주문 만료(캐파·재고 반환)는 `scheduler` 컨테이너가 매분 돌린다.
- MySQL로 테스트:

```bash
docker compose exec -e APP_ENV=testing -e DB_DATABASE=siren_test -e SESSION_DRIVER=array -e CACHE_STORE=array app php artisan test
```

## 혜택 (마일리지 · 쿠폰 · 스탬프)

- 고객 = 휴대폰 번호. 비회원 음식 주문에도 적립되고, **쓰려면** 휴대폰 인증(비회원) 또는 회원 로그인이 필요하다. PG에는 번호 대신 `customer_key`를 user_id로 보낸다.
- 마일리지: 매장 주문은 업체가 상품마다 정한 적립금(업체 부담)을 **수령 시** 지급, 공연 티켓은 관람 후 결제액의 1%(운영사 부담). 취소하면 쓴 마일리지를 돌려주고, 수령 후 환불이면 적립금을 회수한다.
- 쿠폰: 정액·정률·무료 상품, 공개 받기·코드 입력·직접 지급. 운영사 쿠폰은 운영사가, 업체 쿠폰은 업체가 부담한다(정산 반영).
- 스탬프: 매장(메뉴 1개당 1개) · 공연 관람(티켓 1매당 1개). 다 모으면 보상 쿠폰 자동 발급.
- 모든 기록은 `benefit_ledger`에 추가만 하고, 행마다 직전 해시를 이어 붙인다(위변조 탐지). 매일 03:00 머클 루트를 `ledger_anchors`에 남긴다. 블록체인이 정해지면 `BlockchainAnchor` 구현만 바꿔 루트를 체인에 올린다(개인정보는 올라가지 않음).

## NFT 티켓 · 웹3 준비

- 회원이 예매한 좌석 1장 = NFT 1개(ERC-721 형식). 예매하면 발행, 취소하면 소각, 입장하면 "사용됨"으로 바뀐다.
- **양도 불가(소울바운드)**: 리셀을 막고, 거래되지 않으므로 가상자산 규제나 중국의 NFT 2차 거래 금지와 부딪히지 않는다.
- **운영사 보관 지갑**: 지갑은 고객(휴대폰 번호) 단위로 하나. 팬은 지갑·개인키를 몰라도 되고, NFT 티켓과 앞으로의 마일리지 토큰이 같은 주소에 모인다.
- 메타데이터 `/nft/tickets/{tokenId}`, 이미지 `/nft/tickets/{id}/image.svg` — 공연·좌석만 공개하고 이름·번호는 넣지 않는다(체인에 올라가면 지울 수 없다).
- 입장: 팬 화면의 입장 코드는 30초마다 바뀌는 서명 값이다. 캡처한 화면은 통과하지 못하고, 한 번 검표하면 다시 쓸 수 없다. 운영사 `/admin/check-in`에서 스캔한다.
- 체인은 미정이다. `TicketChain`(티켓)·`BlockchainAnchor`(원장) 구현만 바꾸면 되고, 지금은 `local`로 기록만 남긴다.

### 카이아 테스트넷(Kairos) 연동

컨트랙트 `app/blockchain/contracts/SirenTicket.sol` — 양도 불가 ERC-721 + ERC-5192(잠긴 토큰). 운영사만 발행·소각·입장 표시, 전송·승인은 모두 막힘. 컴파일 결과는 `app/blockchain/build/SirenTicket.json`(solc 0.8.24, london).

컨테이너 명령은 꼭 웹 서버 계정(`-u www-data`)으로 실행한다(root로 돌리면 로그 파일 권한이 바뀌어 사이트가 로그를 못 쓴다).

```bash
docker compose exec -u www-data app php artisan nft:operator
```

```bash
docker compose exec -u www-data app php artisan nft:status
```

```bash
docker compose exec -u www-data app php artisan nft:deploy
```

1. `nft:operator` — 운영사 키를 만들고 **주소만** 보여 준다(키는 볼륨 `storage/app/.kaia_operator_key`, 권한 600).
2. 그 주소로 Kairos 수도꼭지(faucet)에서 테스트 KAIA를 받는다(로봇 확인이 있어 사람이 해야 한다).
3. `nft:status`로 잔액 확인 → `nft:deploy`로 컨트랙트 배포(주소는 설정에 저장).
4. `docker-compose.yml`의 app·scheduler 환경에 `SIREN_NFT_CHAIN: kaia`를 넣고 다시 띄우면, 이후 예매부터 카이아에 발행된다.

- **배포됨 (Kairos 테스트넷)**: 컨트랙트 `0xccef08c31beec889d9951d3647a3eef95bcbcf3e`, 운영사 `0xa103ca4fd3a4f92c92dcf1426d0c350c8d79e13a`. 지금 `docker-compose.yml`은 `SIREN_NFT_CHAIN: kaia`라서 한국·해외(중국 제외) 거주 회원의 예매가 이 컨트랙트에 발행된다. 체인에서 확인한 것: 발행(소유자·잠김), 양도 시도 거부(`Soulbound()`), 입장 표시(`used`), 취소 소각.
- 메타데이터 주소(baseURI)는 지금 `http://localhost:8090/nft/tickets/`라 외부 지갑에서는 그림이 안 보인다. 실제 도메인이 생기면 `setBaseURI`로 바꾼다.
- 거주 국가가 중국인 회원은 체인에 올리지 않고 로컬에만 기록한다(`config/siren.php`의 `nft.offchain_residence`).
- 체인 전송이 실패해도 예매·취소·입장은 막지 않는다. 토큰을 "대기"로 두고 `nft:retry`(5분마다)가 다시 보낸다.
- 수수료는 운영사 지갑이 낸다. 운영 단계에서는 운영사 키를 KMS·HSM 서명으로 바꾸고, 발행은 큐로 보낸다.

### 거주 국가

가입할 때 휴대폰 국가번호와 따로 **사는 나라**를 받는다(내 계정에서 변경 가능, 비밀번호 확인). 체인 기록과 향후 코인 기능은 국적·접속 위치가 아니라 거주 국가로 정한다 — 한국에 사는 중국인은 한국 거주, 한국에 잠시 온 중국 관광객은 중국 거주.

### 마일리지 → 토큰 → 글로벌 코인 (계획)

지금 마일리지는 해시 체인 원장과 고객 지갑 위에서 돌아가므로, 체인이 정해지면 잔액을 토큰으로 옮길 수 있다. 다만 **거래·환전 가능한 코인으로 여는 순간 법적 성격이 바뀐다**:

- 한국: 가상자산이용자보호법·특정금융정보법(가상자산사업자 신고, ISMS, 트래블룰), 결제·충전 기능이 있으면 전자금융거래법(선불전자지급수단)
- 중국: 가상자산 거래·발행 금지 — 중국 회원에게는 코인 기능을 열 수 없다(포인트로만 유지)
- 해외: 국가별 증권·결제 규제 (미국 SEC, EU MiCA 등)

그래서 단계를 나눈다. ① 지금: 서비스 안에서만 쓰는 포인트(원장·지갑 준비 완료) → ② 양도 불가 포인트 토큰(체인 기록만) → ③ 법률 검토 후 거래 가능 코인. ③ 전에 반드시 법무 검토가 필요하다.

## 다국어 (한국어 · 中文 · English)

- 화면 위쪽에서 언어를 고른다. 처음엔 브라우저 언어로 정하고, 회원은 고른 언어가 계정에 저장된다. 한 화면에는 한 언어만 나온다.
- 번역문은 `app/lang/zh_CN.json`, `app/lang/en.json` — 한국어 문장이 키라서, 번역이 빠진 문구는 한국어로 보인다. 자동 번역 서비스는 쓰지 않는다(중국에서 막히고, 약관·환불 문구는 정확해야 한다). 한국어가 아닌 화면에는 "약관·환불 규정은 한국어 원문 우선" 안내가 붙는다.
- 지금 번역된 곳: 공통 레이아웃(머리말·메뉴·바닥글), 회원가입·로그인·새 기기 인증·2단계 인증·비밀번호 재설정·내 계정, 인증번호 문자·메일. 나머지 팬 화면(공연·예매·매장 주문·혜택)은 다음 단계.

## 회원 보안

- 운영사·업체 계정(`users`)과 팬 회원(`members`)은 테이블·로그인 세션이 분리되어 있다.
- 로그인 시도 제한(IP·계정), 5회 실패 시 잠금(15분→1시간→24시간), 없는 계정·틀린 비밀번호 같은 문구.
- 처음 보는 기기는 인증번호 추가 확인(30일 신뢰), 선택 2단계 인증(OTP 앱, 복구 코드), 비밀번호 변경 시 다른 기기 세션 즉시 종료, 로그인 기록 공개.
- 해외 회원: 국가번호 휴대폰 13개국. 중국은 해외 문자가 막히는 경우가 많아 이메일 인증을 기본으로 하고, 개인정보 국외 이전 동의(PIPL)를 따로 받는다.
- Docker 앱 키는 `storage/app/.app_key`(볼륨)에 한 번 만들어 계속 쓴다. 재빌드해도 암호화된 2단계 인증 비밀키를 읽을 수 있다.

## 정산 규칙

- 기간 안에 **수령완료**된 주문을 업체별로 묶어 정산서를 만든다. 지급액 = 매출 − 업체 쿠폰 − 수수료 − 수수료 부가세 − 업체 부담 적립금 − 공제. 수수료는 업체 쿠폰을 뺀 금액에 붙는다. 운영사 쿠폰·마일리지 사용분은 운영사가 채워 준다.
- 묶인 주문은 정산완료로 바뀌고 다시 묶이지 않는다. 환불된 주문은 매출에 들어가지 않는다(정산서에 건수만 참고 표시).
- 운영사가 실제로 송금한 뒤 "지급 완료로 표시"한다.

## 아직 안 된 것

- 실결제(페이레터) 연동 — 지금은 개발용 mock 결제. `config/siren.php`의 게이트웨이만 바꾸면 된다.
- 입장 QR 검표, 좌석 직접 지정, SMS 알림톡, 원본 DB 이력 이관, 업체 계정 추가·비밀번호 변경 화면.
- 문자 발송사·메일 발송(SMTP) 연동 — 지금은 개발용(화면 표시). 해외 문자는 국제 SMS 지원 업체가 필요하다.
- 블록체인 선택과 앵커 구현, 중국어 화면(zh-CN), 위챗 로그인, 중국 접속 속도(Google Fonts 등 해외 리소스 대체).
