## 0. 요약 (솔직하게)

새 시스템은 **사이렌오더(매장 주문·픽업)와 매장 운영 쪽은 대부분 갖췄지만, 지금 상태로는 다담다를 바로 대체할 수 없다.**
이관 전에 반드시 만들어야 하는 것 다섯 가지:

1. **실결제 없음** — 원본은 페이레터(카드·네이버페이·삼성페이·카카오페이). 새 시스템은 가짜 결제뿐이다.
2. **SNS 로그인 없음** — 원본 구매자는 네이버·카카오·구글·애플로만 로그인한다(아이디/비번 폼은 숨김). 새 시스템은 휴대폰·이메일 가입만 있어 **기존 회원이 로그인할 방법이 없다.**
3. **공연 없이 주문하는 화면 없음** — 원본 매장은 공연과 상관없이 늘 주문을 받는다. 새 시스템 팬 화면은 `공연 → 매장 → 메뉴` 순서라 공연이 없으면 주문할 수 없다. (주문 처리 로직은 공연 없이도 동작한다 — 화면만 없다)
4. **기존 데이터 이관 도구 없음** — 상품·생산·정산·판매 데이터를 옮기는 스크립트가 아직 없다. (회원 등 나머지는 가져오지 않는다 — 2-0 참고)
5. **문자 발송 없음** — 가입 인증·준비 완료 알림이 로그로만 남는다. (원본 SMS 사용 여부는 [확인 필요])

## 2. 데이터 이관

### 2-0. 범위 (2026-11-17 결정)
- **가져오는 것: 상품 · 생산 · 정산 · 판매 데이터만.** DB 전체를 옮기지 않는다.
- 한 번에 덤프를 붓지 않고 **항목별로 하나씩 새 구조에 맞춰** 가져온다 (상품 → 생산 → 판매 → 정산 순, 항목마다 건수·합계 대조).
- 상품이 판매자·매장에 속하므로 **판매자·매장 정보는 상품을 붙이기 위한 최소한만** 만든다 (업체명·사업자정보·매장). 판매자 로그인 계정은 새로 만들고 비밀번호는 판매자가 직접 설정한다.
- **가져오지 않는 것:** 회원(정상·휴면·탈퇴), 마일리지 잔액, 포인트, 커뮤니티, 스탬프 잔여, 약관 동의 이력. → 기존 고객은 새 시스템에서 새로 가입·주문한다.
- 따라서 2-2 의 회원 비밀번호·휴면 분리 문제는 **해당 없음**. 판매 데이터에 들어 있는 구매자 이름·전화번호는 판매·정산 대조에 필요한 범위로만 옮긴다 [필요 범위 확인].
- 아래 2-1 ~ 2-3 은 원본 전체를 조사한 기록이다. 실제 이관은 2-0 범위만 한다.

### 2-2. 이관하며 반드시 처리할 것 (확인된 함정)

1. **회원 비밀번호는 옮길 수 없다.** 원본은 암호화된 함수(`Happy_Secret_Code`)로 만든 32자리 값이라 알고리즘을 알 수 없다(md5·sha1과 다름 확인).
   - SNS 회원(대부분): `user_id = "{sns_site}_{sns_id}"` → **SNS 고유 ID로 연결하면 비밀번호 필요 없음.** (로컬: naver 53 · kakao 45 · google 35 · apple 11 · 빈 값 6)
   - 판매자·아이디 회원: **첫 로그인 때 비밀번호 재설정** (휴대폰·이메일 인증). 또는 원본 PHP 를 잠깐 검증용으로 두는 방법 — 복잡해서 비권장.
   - SNS 값이 비어 있는 6명은 개별 확인.

  1. 원본 관리자에서 arena1 주문내역을 다시 읽어 `arena1_orders.json` 을 새로 만든다 — **주문마다 정산일시(`settled`)도 같이 읽는다** (주문내역의 '정산완료 날짜', 또는 정산 완료목록의 '상세보기' = 그 회차 주문 목록).

  3. `php artisan dadamda:import-orders --store=<매장>` — 새 주문은 넣고, 아직 정산서에 묶이지 않은 이관 주문은 원본의 바뀐 상태(수령완료 → 정산완료)로 맞춘다.
  4. `php artisan dadamda:import-settlements --store=<매장>` — 새 회차만 정산서로 만든다 (이미 넣은 회차는 건너뜀, 금액이 다르면 멈춤).
  - (생산 이관은 아래)
  - 정산일시(`settled`)가 있으면 그 회차 주문만 묶고, 없으면 '정산 시각 전에 산 주문'으로 묶는다. 운영 서버에 처음 넣을 때 원본 정산이 이미 두 번 이상이면 정산일시가 꼭 있어야 한다 (11-11 주문 2건은 11-12 회차가 아니라 다음 회차).
